## 验证记录

- `npm run check`：通过（应用脚本、内联脚本与 TypeScript）。
- `npm test`：**531 项通过**。新增覆盖：草稿所有权/去重/上限/快照、真实 QR 解码、依赖副本一致性、外链指标、评论12请求抢1额度、满额幂等、迟到请求/超时/路由取消。
- `npm run build:standalone`：通过；输出到 `dist-standalone`，没有部署。构建保留已有动态导入告警，不把它报告成运行失败。
- 微信旧草稿 `node --test tests/wechat-auth.test.mjs tests/wechat-frontend.test.mjs`：**28/28**；不等于与最新主线已整合。
- 浏览器真实前端：发布完成页 → 加入名片 → 从原卡继续 → 3件作品草稿 → 预览 → 保存。公开 API 核对旧卡仍2件、新卡3件，旧卡与原版本仍可读。
- 分享图实际下载成功；独立 `sharp` 解码 PNG + `jsQR` 解码得到正确的本地 `/c/<id>`，1200×1440。真实 QR 单元测试另覆盖正式域名 URL、Unicode 和 220/290px 尺寸。
- 原型三轮走查：同一1410×770视口，首屏完整作品行 R1=0、R2=1、R3初稿=2、R3修订=4。只是可见信息测量，不宣称真人效率倍数。
- 390px iframe：作品列表/编辑器无横向溢出；初稿预览遮住选作品，已改为可展开；桌面仍并排实时预览。不是手机浏览器真机测试。
- 实际 Orbit 视频读得7.95945秒、1800×1120；预览播放/静态回退通过。云端720p编码尚未实现。

证据：`design/morning-review/screenshots/` 中的空间、名片编辑、网站数据、Logo、手机原型、分享图与弹窗。详情及未执行项见研究文档。

## 明早建议验收顺序

先看空间/作品页是否顺手，再走一遍名片选择到保存；切到网站数据检查你最关心的指标；最后挑 Logo 方向。代码功能可在8881本地站验收，原型不要当正式功能上线。视频/微信的下一步先解决服务选择和外部条件，再开展小范围真实试验。
