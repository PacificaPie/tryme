## 独立的内容下架状态

新增迁移 `0024_content_moderation.sql`、`moderation-service.mjs` 和管理页 `/site.html#/admin/moderation`。`FUNTRACK_MODERATOR_IDS` 是服务端精确账号白名单，以逗号/空白分隔，独立部署使用 `clerk:user_…`。未配置时管理 API 返回 403，不能使用邮箱、姓名或客户端传入的角色获得权限。测试和正式 Clerk 的用户 ID 分别配置。

运营人员先查询作品或名片 ID、核对目标和影响名片数，再填写原因执行下架/恢复。每次处置追加操作者、原因、时间、目标、修订号和幂等回执，禁止修改/删除既有审计记录。并发操作采用原子修订号条件；响应丢失后重试不重复写入，旧操作重放不覆盖后续恢复决定。页面遇到状态冲突要求刷新，不把旧决定自动应用到新状态。

作品下架后：

- 当前作品、旧版本列表、所有历史游戏与版本/metadata 封面、公开 Feed 封面和视频不可读取。
- 包含该作品的所有已保存名片暂停访问，包括公开 `/c/…` 页面的 HTML/OG、JSON、封面和 Feed 名片；整张名片不返回部分旧内容。
- 作品/名片列表及作者主页不重新露出内容；不会回退展示某张更旧的名片。
- 评论上下文、互动消息内容和统计展示也屏蔽该作品，原始历史记录保留。
- 旧发布/名片回执、新名片保存、旧试玩会话和版本/metadata 写入不能绕过下架。数据库触发器补住“预览后下架、随后保存”的竞态。
- 后台媒体任务会跳过受限作品；已在处理的结果不能通过公开入口暴露。

恢复只撤销对应的运营限制，不改变作品归档/Feed 选择、用户删除的名片、游戏版本或名片快照。名片单独恢复后，若它关联的作品仍被下架，名片继续不可访问。

范围是平台托管的作品、名片及相关访问入口；不删除第三方网站内容，也不撤回已经下载/打开的副本。新响应使用 `no-store`，以前发出的私有封面缓存可能在原 1 小时有效期内仍被浏览器保留。这不是新增账号封禁、个人资料/头像审核或单条评论处置系统。

- 14 个永久对象，合计 7,028,011 字节；本地 R2 取回后哈希一致，游戏文件还与数据库版本的 `content_hash` 对照。

工具 `scripts/restore-rehearsal.mjs` 只允许云端 R2 GET，数据库导入固定为 `--local`。本次实测发现原始导出的依赖顺序不能直接用于该本地环境；工具先创建表和外键依赖的唯一索引，再导入记录，最后创建触发器，避免重放历史通知等副作用。SDK 也使用与 Wrangler 一致的 `state/v3` 存储路径。

```sh
# 事先准备 SQL 导出，再运行。不会修改正式 D1 或 R2。
node scripts/restore-rehearsal.mjs \
  --export .backups/<snapshot>/production.sql \
  --source-config wrangler.standalone.production.jsonc
```

临时捕获草稿和未被永久业务引用的孤立文件不纳入此次 R2 恢复；草稿的 SQL 记录被保留，但不承诺这些短期预览继续可用。这是“当前快照能恢复”的证据，不是定期备份、历史时间点、跨账户恢复或真实登录演练。方法参考 Cloudflare 的[导出与导入说明](https://developers.cloudflare.com/d1/best-practices/import-export-data/)；D1 Time Travel 与这次离线导出恢复是不同机制，见[官方说明](https://developers.cloudflare.com/d1/reference/time-travel/)。
