# 作品版本界面

本文件描述本地开发代码，不代表生产功能已经部署。接口契约见 `api-contract.md`。

## 入口

- 我的作品 → 更多 → 更新版本：`#/studio/works/:workId/update`。
- 我的作品 → 更多 → 版本历史：`#/studio/works/:workId/versions`。
- 历史条目标题 / 试玩：`#/studio/works/:workId/versions/:versionId`，页面标题和游戏工具栏始终显示实际版本。
- 外链作品没有更新与历史入口；第一阶段不改变作品名称、介绍或来源类型。

更新页仅保留“发布新版本”作为准备完成后的主按钮；GitHub 尚未导入时，主动作是“导入并构建”。文件预览和返回入口在“更多”，封面替换独立折叠。历史页以“更新版本”为主动作，历史条目的切换入口折叠；切换前显示精确的 `vN → vM`。

## 草稿与提交

`public/versioning.js` 使用独立的账户 + workId 草稿。文字、首个 revision 基线、幂等键、构建 ID 保存在 sessionStorage；文件按同一账户 + workId 存入 IndexedDB。它不借用新建作品的 `publishDraft`，也不清理其他作品草稿。

返回、重新打开及重新登录同一账户会恢复草稿。等待构建期间返回不取消服务端构建，重新打开同一草稿继续轮询。请求失败保留文件和说明；网络结果不确定时按钮变为“确认上次发布结果”，沿用原幂等键和原 expectedRevision。

检测到版本冲突后，保留草稿并禁用发布。只有点击“按当前版本继续”，才重新读取当前版本、更新基线及创建新提交键。修改文件或说明属于新提交意图，但不会自动刷新 revision。

回滚的未确认操作保存在单独的 `:activate` 记录中；返回历史页可按原键确认结果。发布或切换成功会清除发现缓存。已开始的游戏不因后台结果被替换或跳走；用户重新打开普通作品链接才采用当前版本。

## 预览与名片

本地草稿预览使用 `iframe sandbox="allow-scripts"` 与前置 CSP，仅允许内联脚本/样式及 data/blob 媒体，不发出正式试玩事件。GitHub 草稿预览复用作者所有的 `/api/builds/:id/preview`；父页面也保留相同 iframe sandbox。

名片保存同时发送 workIds 与从 `preview.works` 取得的 workRefs，固定预览时的 versionId。作品更新不会重写旧名片或内存中的 preview。页面访问及外链事件在首次创建时冻结版本；会话事件继续绑定最初获得的 sessionId。当前历史私密反馈界面只读，没有新反馈提交或重试逻辑。

新版名片预览带 `payloadSchema:2`。旧缓存预览仍保留原 saveKey，页面要求明确重新生成预览后才能保存；重新生成时才创建包含固定版本引用的新请求及新键。升级页面不会把 workRefs 静默加到已经使用过的旧请求键上，也不会自动再次覆盖名片。

## 验证

`node --test tests/versioning-ui-state.test.mjs` 覆盖：基线与重试键保持、显式重新选择基线、历史本地版本不继承最新 GitHub 来源、名片引用与事件版本固定、未发布预览 CSP。

真实 D1/R2 与浏览器验收应另记录：v1→v2→v1→v3、失败重试、双标签冲突、旧名片/会话、更新页返回恢复、本地/GitHub 预览及手机布局。此说明本身不证明这些验收已通过。
