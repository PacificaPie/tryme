# F02 · 视频预览与生成方案

核查日期：2026-11-18。结论：先提供真实交互录制和稳定的静态回退，再评估 AI 剪辑；纯生成宣传片需要单独标注。此次已交付本地录制/播放实验，没有付费调用模型，也没有上线队列。

## 已完成的实验

`design/morning-review/video-lab.html` 可从本地 Orbit Canvas 录制 8 秒，无麦克风、桌面或登录态采集。通过 Chrome 实际启动游戏、录制并操作方向键后得到 `assets/orbit-preview.webm`：浏览器测得 **7.95945 秒、1800×1120、约 521 KiB、无声音**。这是现有 Canvas 在设备像素比 2 下的原始录制，不是已完成的 720p 云端转码。

原型 `#/video` 默认 `preload=none`，悬停 450ms 后静音预览，离开、页面隐藏或达到 8 秒停止；手机/键盘可主动播放；减少动态效果或省流量偏好下不自动播放。视频缺失继续显示静态封面。实际测试播放与 404 回退；当前样例是 WebM，Safari 和微信内置浏览器兼容性尚未实测。产品阶段应提供 H.264 MP4，并保留封面回退。

## 三种路线

| 路线 | 用途 | 能保证什么 | 仍需验证 |
|---|---|---|---|
| 真实操作录制 | Feed 预览首选 | 画面来自具体作品和版本 | 不同游戏启动/引导、镜头选择、录制成本 |
| 真实录制 + AI 挑片/字幕/剪辑 | 降低作者制作负担 | 保留原始操作作为可核对依据 | 对作品理解、素材隐私、剪辑质量 |
| 图片/文字生成视频 | 可选概念宣传片 | 只能保证符合提示，不能证明交互存在 | UI 字体失真、玩法幻觉、品牌一致性 |

纯生成视频不宜自动伪装为试玩录屏。不能根据“生成画面好看”推断真实游戏效果。

## 建议实现切片

1. **录制/上传 MVP**：作者选择作品版本并主动生成或上传预览；作品发布不等待视频。第一版提供手动操作录制，失败可重新录或直接跳过。
2. **异步任务**：`queued → capturing → encoding → ready / failed`；以 workId + versionId + contentHash 固定对象键。同版本重复请求复用任务，更新版本不能静默替换旧名片的视频。
3. **隔离执行**：不在带平台密钥、Clerk 会话或构建器权限的环境内执行上传作品。用无用户会话、限制出网、超时和资源上限的独立录制环境；任意 HTML 均按不可信代码处理。
4. **归一输出**：最多 8 秒、目标 720p、目标 ≤2 MiB、移除音频、MP4 + 封面。当前仓库的 Workers 不能直接等同于可运行 FFmpeg 的容器；云端编码执行环境需要单独选型。
5. **Feed**：同一时刻只播放一个可见视频；进入视口才允许请求；数据节约/减少动态效果、无 hover 的设备默认静态。手动控制具备可访问标签，失败不能阻断打开作品。
6. **计量与隐私**：区分预览曝光与真实打开/操作，不将自动预览记为试玩；只上传用户授权且可公开的素材。记录 provider/model/version/cost/latency，错误日志不存密钥。

## 下一次小试验

使用同样的 3 件作品，比较原始录制、AI 剪辑和生成宣传片。每条评估：玩法是否真实、首 2 秒是否看懂、文本是否可读、是否虚构功能、生成等待、实际费用、愿不愿意点开。

今晚仅完成其中 1 件作品的真实录制。付费模型试验待确定服务账号、可用地域、素材授权和费用上限后再跑；不要把官方单价写成已经测出的总成本，也不承诺自动生成能适配所有作品。
