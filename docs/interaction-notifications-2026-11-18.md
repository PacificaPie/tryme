# 站内互动消息

登录后，头像左侧的铃铛统一承接作品点赞、评论点赞、作品评论、回复和新增关注。未读显示红点；桌面打开弹层，600px 以下打开完整消息页。列表支持全部／评论／点赞／关注筛选，同一目标、同一 UTC 日的点赞聚合，展开可分页查看每位点赞者。

打开列表不清除未读。点开消息并成功保存已读后，进入作品、原评论上下文或关注者主页；支持全部已读。头像可直接打开个人主页。没有邮件、系统推送、轮询计时器或通知本地存储；首次加载、路由变化、窗口重新聚焦会检查红点（15 秒节流），打开列表和手动刷新会读取最新消息。

## 创作中心与历史记录

创作中心移除重复的“互动”导航，保留“我的作品”和“数据”。旧 `#/studio/feedback` 链接转到 `#/notifications?filter=comment`，保留作品筛选。新消息页底部“历史记录”仍可进入全部评论记录和历史私密反馈；显式 `?tab=history`、`?tab=legacy` 继续可用。

## 数据与一致性

- 追加迁移 `0021_interaction_notifications.sql`、schema 和 journal。0019、0020 在本轮开始时分别由上传和微信分支占用；本迁移只依赖既有作品／评论／点赞／关注表，不依赖这两项功能。合并时保留各自迁移，不修改已应用编号。
- SQL 触发器在原互动事务中创建通知，失败会连同源写入回滚，无需改动各业务写入处理器。排除自通知；回复优先通知被回复评论的作者，作品作者不同时再通知作品作者，避免同一人收到两条。
- 不回填迁移前的互动；旧评论仍在历史记录中。取消点赞／关注后对应消息失活并视为已读，重新点赞／关注复用原记录，不重新置未读或顶到最新。这是本版防重复提醒的明确口径。
- 服务端按登录用户隔离收件箱，读写都要求匹配 `expectedRecipientId`，沿用已有认证和写入 CSRF 校验。异步响应绑定原账号和请求版本；超时可重试，切换账号清空旧内容，失败不乐观清红点。
- 分页固定最大序号快照；点赞组使用包含已失活记录的稳定排序位置，取消最新点赞不会让该组在下一页重复。点开一个组仅标记所见序号及以前的成员，全部已读仅处理该次列表快照，新到消息保持未读。
- 只存事件引用和已读状态，内容、名字、头像实时读取。内容删除或对收件人不可访问时显示不可用提示，不返回旧正文和链接；已归档作品只向作品本人保留可访问上下文。未实现通知保留期清理策略。

## 验证与复现

自动测试覆盖收件人归属、去重、事务失败／请求重试、取消／恢复、点赞聚合与成员分页、分页快照、已读竞争、认证／CSRF／跨账号隔离、删除与归档、前端超时／乱序响应／重试和准确跳转。

```sh
npm run check
npm test
npm run build:standalone
node tests/integration/notifications-d1.mjs
node tests/fixtures/notifications-browser-server.mjs
```

D1 脚本在随机独立目录使用 Wrangler `--local` 应用全部迁移，再回放真实 router 捕获的 45 条 SQL，验证触发器、聚合、成员列表与已读操作。浏览器 fixture 只监听 loopback，使用真实前端、router、SQLite 和虚构账号，不读取云端身份或作品。它在启动时输出本地地址；控制页可切换模拟账号、空态、503 失败和新增消息。

已进行本地浏览器验证：桌面弹层与键盘 Esc／焦点返回、手机整页入口、320/360px 无横向溢出、中英／明暗主题、全部已读与刷新持久化、点赞者列表、回复定位、账号切换后清空旧消息、失败重试、游客登录门槛，以及旧入口和历史记录。预览截图是虚构数据，保存在忽略目录 `.preview/notifications/`。

本次仅开发和本地验收，不执行云端迁移或部署；真实 Clerk 双账号、生产数据库和跨浏览器上线验收仍需在明确目标环境下执行。上线时必须先应用新增迁移，再启用使用它的 Worker 代码。

## 并行开发边界

实现位于独立 clone 的 `feat/interaction-inbox` 分支。主要代码在新增 notification 模块；共享 `server.ts` 仅导入／实例化／分发服务，共享 `site.js` 仅挂载铃铛、页面路由与历史入口。未改点赞、评论、关注的原处理器，未在其他开发目录 checkout/reset，也未合并或部署其他分支。
