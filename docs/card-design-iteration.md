# 名片与 Feed 迭代记录

2026-11-16。本文区分原方案的实际代码、已选定的设计方向与外部平台限制。原方案已只读检查，未在本轮逐个渲染；下述视觉判断来自代码与素材组织，不是设备视觉验收。实现以主代理当前分支为准，本文件不宣称功能已上线。

## 本轮组合

一级导航固定为 **Feed / 创作中心 / 名片**。Feed 展示作品并提供点赞、分享；创作中心负责发布、作品、数据和反馈；名片入口承担公开名片浏览及自己的名片制作。浏览他人名片与编辑自己的名片要有明确入口，不能把公开列表变成编辑表单。

卡中展厅继续作为主体验，不把九种开屏拼成一条动画。选定的实现方向是：

1. 移除卡片外部操作工具条，把展开入口投影到卡面底边，翻面入口放在卡面角落；点击卡主体也可展开。投影热点用可聚焦的真实按钮，不能只画在 Canvas 上。
2. 展开后在地面提供进入展厅的入口，相机进入**同一间、同一批作品**的房间。近景有明确返回位置；浏览作品后恢复展开、角度、分组及远近状态。静止时不循环播放，不用首次必看的长开屏。
3. 悬停画框时显示名称和可点击反馈；点击直接进入对应作品页。手机没有悬停也能完成同样操作；拖动不误触作品，竖向页面滚动不被水平旋转截断。
4. 卡背展示选中作品中的真实代表作封面、作者签名/姓名、一句介绍及可选网站。提供 ink、ivory、cobalt 三种风格，正文保持足够对比。三种风格都是模板选择，本轮没有计费。
5. 根据模型包围盒和当前视口适配相机，减少无效留白；切到卡背、展开、进入近景、窗口变化时分别校验。保留 reduced-motion、HTML 作品入口和 WebGL 失败回退。

以上是本轮实现决策。代表作、签名、介绍、网站和风格应进入新名片快照；旧快照缺失字段时采用确定的兼容默认值，不能用最新作者资料覆盖旧卡。网站仅接受 HTTP(S)，不把装饰性头像、假编号或样例统计当成作者信息。

## Feed 点赞与分享的语义

点赞是对作品的操作，应按用户与作品唯一保存，重复点击能取消；并发、重试或失败后不累加虚假数量。若使用乐观界面更新，失败要回滚。点赞不改变已保存名片中的作品快照，也不冒充试玩次数。

分享按钮先打开链接弹窗，以复制链接为主动作；浏览器支持时提供“更多分享方式”。取消系统分享不自动写成成功，复制成功仅提示链接已复制。可以记录入口点击或复制行为，但不把它标成“已分享到微信/朋友圈”。名片分享应指向稳定快照，作品分享指向正确作品。当前站点 owner-only，复制链接不会放宽接收者权限；对外访问范围是另一项明确决策。

## 微信：可确认事实与本轮选择

调研日期为 2026-11-16，来源仅使用微信官方文档、官方 SDK 或 W3C 规范。旧公众号 JS-SDK 地址已返回迁移页，现行文档在服务号网页开发路径。网页检索工具无法读取部分微信页面，随后直接读取官方提供的 HTML/Markdown，返回 HTTP 200；没有用社区转载替代事实依据。未登录微信开发者后台，未验证我们拥有服务号、小程序资质或可配置域名，也未做微信真机分享测试。

| 方式 | 已核实的能力与限制 | 对 Funtrack 的设计判断 |
| --- | --- | --- |
| 普通 H5 链接 / 浏览器系统分享 | 普通网页链接可在微信聊天中打开。Web Share 的目标由浏览器和系统提供，需安全上下文及用户激活，网站不能保证出现微信或指定发送对象。[微信起步指南](https://developers.weixin.qq.com/doc/service/guide/h5/start.md)、[W3C Web Share](https://www.w3.org/TR/web-share/) | 本轮支持链接及可用时的系统分享，不声称这是微信原生分享卡片；复制链接作为兼容出口。 |

建议本轮完成 H5 卡片与 Feed 的真实操作，再把微信定制分享作为有明确账号、域名和真机验收条件的后续项。做小程序并非实现链接分享的前置条件。

## 最少验收

- 卡面热点随投影正确移动，360px 下不重叠；能键盘聚焦且读出展开/翻面/返回含义。
- 开合、翻面、进入近景、返回都可中断；切换 reduced-motion 后状态落在正确终点，不突然回到原封面。
- 拖动不误开作品、点击不点穿墙；同一房间远近两种视角呈现相同作品与版本。作品往返保留状态。
- 代表作缺图、长姓名/介绍、空网站和旧快照能正常显示；网站按钮不会把文字解释为脚本。
- 1、2、3、9、10、30 件作品检查相机包围、分组和导航；静止、隐藏及卸载时不持续耗费渲染资源。
- 点赞刷新后与数据库一致；分享取消不算成功、复制仅确认复制；无微信配置时不出现误导性的“已发微信”回执。
