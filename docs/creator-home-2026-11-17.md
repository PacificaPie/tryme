# 创作者主页、名片工作台与头像（2026-11-17）

## 当前信息层级

- 顶栏保留 Feed／创作中心／名片。个人主页与关注列表从头像菜单进入；个人页面不会选中顶栏标签。
- 个人主页采用「桌上名片」：身份与关注操作、独立名片封面、完整公开作品列表。精选作品仍出现在完整列表中，各模板共用封面入口。
- 名片页 `/cards` 是自己的名片工作台，只读 `/api/cards/me`。提供当前名片的查看、分享、重新制作与删除，以及五款模板的体验入口。不存在收藏别人名片的功能；别人的名片从其主页或分享链接查看。
- `/cards/templates/:id` 使用真实模板渲染器与站内示例作品；展厅、收藏桌面及放映册可互动，示例作品打开说明。只有点击「使用这个模板」才更改草稿模板，保留选片和卡片设置；单纯体验不创建名片或试玩会话。
- 「用同款制作」只复制模板与卡背样式，使用本人资料和作品；覆盖已有草稿前有明确提示。
- 关注绑定账号。关注列表仅显示已关注的人，点击头像或姓名进入主页，并可返回列表；Feed 保留发现／关注切换、搜索与排序。

## 资料与内容的数据边界

**个人身份实时联动；名片设计与作品版本保持各自保存的内容。**

- `ft_cards.author_id` 已关联 `ft_profiles.id`，无需新增关系或数据库迁移。原先的问题是读取接口把个人资料也当成快照；现在集中通过 `card-identity.mjs` 投影当前姓名、简介、身份、个人网址、头像。
- 私有当前名片／指定名片／列表、创作者主页、创建与幂等重放响应、匿名名片 DTO、HTML／OG／noscript 全部使用该投影。名片内自有作品的作者姓名和头像同样刷新。
- 当前 profile 存在时，空简介／网址／头像等空值也是权威值，不能通过 truthy fallback 恢复旧资料。仅在 profile 行不存在时保留历史快照作为兼容回退。所有权以数据库作者字段为准，公开 DTO 不暴露账号 ID 或内部资源 key。
- 模板、卡背、签名、选片顺序、作品标题／简介／封面及版本仍属于名片保存内容。读取时不重写历史 snapshot JSON，保存名片也不覆盖当前个人资料。
- 制作页只读展示当前资料并提供统一编辑入口，去掉重复的姓名／简介／角色／网址输入。旧草稿的重复资料会清理；未保存预览在重新加载资料、编辑资料及保存前同步，只有实际变化才换保存幂等 key。账号切换与迟到请求隔离继续保留。
- 公开名片从 BFCache 恢复时重新读取，加载失败或旧请求迟到不会恢复过期资料。

## 头像与组件

- 支持 PNG/JPEG/WebP 上传和四款默认插画，自定义形象以后再做。首字母是无头像时的默认显示，不是可选风格；有头像时提供移除操作。
- 裁切直接拖动圆形预览，支持滚轮、双指缩放、± 按钮、方向键与 Home 重置。指针捕获及取消清理、边界约束和 512×512 导出共用裁切坐标；去掉横纵位置与缩放滑杆。
- 上传仍限制 2 MiB、4096×4096，保存时才提交；取消不写入。历史图片保留，避免破坏历史资源引用。
- 保持现有灰白表面、细边框、按钮、字体及轻量过渡；名片操作桌面和触屏均可直接访问。
