## 本轮可以直接落地的六项编排

1. **Feed 是可比较的作品目录。** 保留 `Feed / 创作中心 / 名片` 一级入口。首屏可将一件真实最新作品放大，与另外几件紧凑列表形成主次，下方接“全部作品”网格；若只有一两件作品，直接呈现这些作品，不重复填满多个栏目。集合名称与排序必须能从数据解释，不凭空添加“为你推荐”“编辑精选”“热门”。默认最新排序已经足够。

2. **卡片展示游戏本身。** 统一横向封面比例，保留标题、作者、最多一行玩法描述，点赞与分享收在底行。封面与标题是同一详情链接；作者是独立入口；按钮不能套在整卡链接中。搜索和一个简洁筛选行即可。现阶段没有真实玩法标签字段，就不生成看似确定的“休闲 / 益智 / 多人”等标签。若保留来源筛选，使用用户能判断的“可直接试玩 / 外链作品”。

3. **详情首屏采用媒体主区与窄信息栏。** 桌面约 2:1：左侧封面/游戏容器，右侧标题、作者、一次简介、版本和唯一“开始试玩”主按钮；点赞、评论数量和分享在次级一行。点击后在原媒体区域加载游戏，避免整页布局突然跳动。外链按钮明确“打开作品”。手机变为单列，作者和简介跟随媒体，按钮保持自然文档流。当前只有封面时就只显示封面，不造多张缩略图或空视频控件。

4. **评论先呈现别人说了什么，再让用户接话。** 内容区为“评论 N”、轻量输入框、真实评论列表。每条为头像或姓名首字、姓名、时间、正文、回复；作者回复用小型“作者”标识。回复最多缩进一层，长列表提供“展开回复”，不要不断右移。默认按时间排序即可，未实现真实评论点赞就不显示热评排序或心形假按钮。空列表只写“还没有评论”，保留输入，不做大型欢迎面板。

5. **创作中心负责回应与监控。** 作品页的评论是读者讨论入口，中心聚合同一批评论并允许按作品筛选；每条能回到原作品或目标评论。评论成功必须以保存回执为准，失败保留草稿和重试入口。评论不强制先选“喜欢 / 建议 / 问题”，也不要求用户先试玩；没有可靠游戏会话关联时，不显示“已玩过”“认证玩家”等标识。

6. **名片选择器展示真实模板差异。** 新模板仍使用同一份作者与已选作品快照。选择页展示真实作品填入后的静态缩略预览，进入预览后才运行交互。每种模板一个名字和一行必要描述即可；取消抽象纸条/色块占位和必须观看的开场。模板增加应带来不同的作品组织方式，而不是只改皮肤或把合作样片中的假作者、假指标带进来。

## 对现有页面最值得删减的部分

以下位置以本轮改动前源码为准；实施后行号可能变化。

| 当前结构 | 建议删减 | 目的 |
| --- | --- | --- |
| `site.js` 的 `renderWork` 同时在标题旁与封面上放“开始试玩” | 保留一个实际主按钮；媒体本身可以作为同一动作的可访问入口，但不再摆两个同等级按钮。 | 减少重复决策与营销式覆盖层。 |
| 同一 `work.desc` 同时在标题下和“关于作品”重复 | 只保留一次；没有更多内容时删除整个“关于作品”侧块。 | 让信息密度来自真实内容。 |
| 每张卡都有“网页游戏”胶囊和右上跳转箭头 | 默认可试玩作品无需重复贴类型；只对外链保留必要提示，去掉每卡装饰箭头。 | 降低标签噪声，让封面与作品名主导。 |
| 公开详情使用三种反馈类型、常驻大文本框和“发给创作者”说明 | 新评论使用一行起始输入，聚焦后展开；移除分类必选。旧私密反馈另按下述边界保存。 | 把任务表单改为对话入口。 |
| `.empty-state` 使用 76px 内边距、虚线边框、重复鼓励文案 | 内容页空态改为短句和必要操作；创作中心保留明确“发布作品”。 | 小数据量时不让占位组件成为页面主体。 |
| `.template-art` 是几条抽象色块，页面外框与模板也使用接近的暖灰色 | 模板预览换为真实内容；外层 UI 使用中性白、清晰正文和细边框，材质与艺术感留给名片。 | 减少演示稿感，同时保留名片个性。 |

现有三列网格、克制字体、细边框可以保留。无需通过全站深蓝、霓虹渐变、玻璃卡片、自动轮播或更大的标语制造“游戏平台”外观。Steam 提供的是内容层级参考；轻量、真实、操作完整才适合当前作品规模。

## 评论改造必须保留的含义

- 原页面明确写过“反馈会发给这件作品的创作者”。**旧反馈不能因为换了 UI 就自动公开。** 新评论使用独立的可见性/存储路径；创作者仍可查看旧反馈，但它不自动进入公开评论数。
- “作品页公开评论”仅指在当前站点访问权限内可见，不能借此自动把 owner-only 站点改为全网公开。后续放开访问需要单独验证用户之间的读取和操作权限。
- 评论至少关联真实 `workId`，写入当时的 `versionId`；从旧名片进入的游戏版本仍按快照打开。若讨论展示跨版本内容，应能区分发生在哪个版本，而不能把旧版本反馈伪装成最新版表现。
- 作者回复、评论删除、回复展开、评论数量等控件只在相应保存与读取能力真实存在后呈现。原有点赞、分享与试玩事件保持各自含义；评论数不是试玩数，也不生成好评率。

## 最少验收

- 0、1、3 和较多作品时没有为了填版重复内容；Feed 返回保留搜索、筛选和滚动位置。
- 详情只有一个显著试玩主按钮；移动端游戏区不被固定输入栏、评论栏或浮层遮住。
- 评论提交失败保留正文，成功刷新后仍在；点击回复有明确对象且可取消；作者标识来自身份匹配。
- 旧私密反馈没有出现在作品公开讨论中；旧名片对应作品版本不变。
- 没有假截图、假推荐排序、假热评、假玩法标签或未经证据支持的玩家认证。
