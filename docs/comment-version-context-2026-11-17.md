# 评论版本关联与精准定位

2026-11-17；分支 `fix/comment-version-context`，基于已发布界面修整 `d1d4816`。另一轮他人主页/关注和微信登录不包含在本轮。

## 行为

- 从旧名片打开 v1 后发表的评论显示 v1；当前 v2 页面发表的评论显示 v2，仍共用讨论区。
- 回复记录回复者页面所处版本，不强行继承根评论版本。版本关联不等于已验证试玩或通关。
- 历史评论、旧客户端省略版本时显示“版本未知”，不猜测或回填。
- 创作中心互动列表携带目标评论 ID；较旧的根评论、第四条以后的回复也能直接定位。定位内容与普通分页分开，返回仍回原互动筛选。
- 评论提交固定页面账号；另一标签页切换账号后拒绝误写，保留草稿和原提交标识。服务端仍只信认证身份。

## 数据与兼容

追加 `0014_comment_version_context.sql`，只向 `ft_comments` 加可空版本外键。`0013` 为未合并微信草稿保留。迁移不修改作品、版本、名片快照、原评论正文、历史事件或试玩会话。

`POST /api/works/:id/comments` 可接收 `versionId` 和 `expectedAuthorId`。新前端始终传入页面版本与挂载时账号。服务端校验版本属于作品、预期账号匹配认证账号，版本加入幂等内容；旧回执仅在保持未知版本时兼容。

`GET /api/comments/:id/context` 是登录后有界读取，最多返回根评论和目标回复。前端验证作品及目标 ID，并单独展示定位切片，不将其当成连续回复分页。

仍保留原统计契约：按版本筛选时评论/点赞指标保持未知；本轮不会把旧评论自动归因到新版本。
