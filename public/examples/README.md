# Funtrack 本地上传测试作品

这三份作品由本项目现有小游戏打包而来，用来检查 HTML 上传、真实交互、平台 SDK 与服务端数据回收。它们不代表外部创作者作品，也不包含玩家数、好评率或其他虚构指标。

| 上传游戏文件 | 上传封面 | 操作 |
| --- | --- | --- |
| `salt-run.html` | `salt-run.jpg` | 空格、↑ 或点按画面跳跃；坚持十八秒，撞到障碍也会结束本局。 |
| `orbit.html` | `orbit.png` | 鼠标、手指或方向键移动光球，依次接触六颗发光星点。 |
| `tiles.html` | `tiles.png` | 点击方格，或方向键选择后按空格／回车翻转。 |

每份 HTML 都是自包含单文件，无外部脚本、样式、字体或图片请求，体积低于 1 MB。封面已嵌入文件，独立封面另用于平台上传。Orbit／九宫格封面由原 SVG 用本地 Sharp 渲染为 PNG；Salt Run 使用项目已有 JPEG。

## 最快的完整测试：点亮九宫格

1. 通过平台文件上传选择 `tiles.html` 和 `tiles.png`，发布并打开作品。
2. 点击“开始游戏”。平台注入的 SDK 自行观察真实输入；示例不会调用或模拟开始事件。
3. 依次点击 **左上格 → 正中格 → 右下格**。三步后九格全部亮起。
4. 也可全程用键盘：开始后画布已获得焦点，初始选中正中格。依次执行：
   - `↑`、`←`、`空格`；
   - `↓`、`→`、`空格`；
   - `↓`、`→`、`空格`。
5. 终局文字应为“3 步，全部点亮！”，分数为 `1000`。自然结束时调用一次 `window.funtrack?.complete?.({ score: 1000, label: '3 步，全部点亮！' })`。
6. 回到平台核对服务端事件与收据。页面结果本身不证明服务端已收到事件。

一份打开的文档只开始一局。再次测试请通过平台重新打开作品，让平台分配新的会话；示例不会在同一会话反复发送完成事件。点击“结束游戏”会停止本局、销毁游戏运行资源，但不会伪造完成事件。会话结束的采集交给平台容器／SDK。

## 暂停与结果边界

- 切到其他标签页时通过 `document.hidden` 暂停帧循环、清除按键；返回时重置时间基准，不补算后台停留时间。
- 真实终局回调才调用 `complete`。Salt Run 撞障碍也是终局，`complete` 不等于通关。
- 单独打开 HTML 时没有平台 SDK 也能游玩；完成结果仅留在页面，不发出网络请求。
- 运行中手动结束或页面离开会清理帧循环、事件监听和 Canvas 缓冲。

## 重建与开发自查

在项目根目录执行 `node examples/build.mjs`。脚本读取 `public/games.js`，内联引擎，移除演示作者资料，仅在生成副本中加入后台暂停；不会修改原引擎。

`node examples/verify.mjs` 对生成文件进行依赖／大小检查，并用实际内联游戏逻辑验证键盘三步通关、点击通关、单次终局、手动结束、隐藏暂停与清理。该检查不等同于真实浏览器视觉检查或服务端入库测试。

下载文件位于 `public/examples/`。ZIP 只是便于下载，平台第一版仍上传其中的单个 HTML，不能把 ZIP 当作游戏上传。

## 新增六款演示游戏

浏览 `/examples/more.html` 可以逐个直接游玩、下载 HTML 与对应 PNG；`/examples/catalog.json` 包含原三款及新增六款的路径、说明、操作和预计时长。所有名称与封面明确标注演示，不代表外部作者作品或社区热度。原三款文件、封面及旧 ZIP 保持不变。

新增六款在 iframe 内使用紧凑布局：隐藏重复标题，保留操作说明，按剩余高度等比缩放并居中 Canvas，操作按钮与重开／结束固定在画面外。独立打开时保留完整标题与封面。Canvas 的实际 CSS 尺寸与指针坐标换算一致，不通过拉伸或裁切挤入容器。

| HTML / 同名 PNG | 玩法与结束条件 | 操作 |
| --- | --- | --- |
| `memory-tide.html` / `memory-tide.png` | 潮汐记忆：十二张卡片，配成六对结束；每次开始重新洗牌。 | 点牌，或方向键选择、空格／回车翻牌。 |
| `pixel-orchard.html` / `pixel-orchard.png` | 像素果园：收集八颗果实获胜，碰墙或身体结束。 | 方向键、屏幕方向按钮，或点击蛇头四周。 |
| `prism-breaker.html` / `prism-breaker.png` | 折光弹球：清除二十四块砖获胜；三球用尽或两分钟到时结束。 | 拖动挡板、点击发球；左右键与空格。 |
| `pulse-lanes.html` / `pulse-lanes.png` | 拍点：完成二十四个视觉节拍，约十五秒结束；无需声音。 | 点轨道或 D / F / J / K。 |
| `mini-sudoku.html` / `mini-sudoku.png` | 四方数独：填满合法的 4×4 数独结束；冲突即时标红。 | 点格与数字，或方向键与 1–4；退格清除。 |
| `arc-hoops.html` / `arc-hoops.png` | 弧线投篮：通过真实抛物线判定入篮，五次出手后结束。 | 拖拽瞄准、松手投篮；左右调角度、上下调力度、空格出手。 |

新增六款的“重新开始”用于同文档内练习；每个文档仍最多向注入的 `window.funtrack.complete` 提交一次自然终局。重新开始不会冒充新的平台会话。若要采集新一局，应使用平台外层的“再玩一次”。“结束本局”停止游戏，不发送虚假的完成；平台退出／返回流程负责会话结束。开始由 SDK 观察真实输入，游戏不制造输入事件。

重建：`node examples/build-more.mjs`。此脚本同时检查六款玩法的实际胜负逻辑、宽度与依赖限制，并用生成 HTML 的真实事件处理器验证开始、手动结束、连续重开、隐藏暂停、离开清理及 SDK 单次完成。覆盖翻牌配对、蛇吃满八颗果实、球撞完全部砖、二十四拍满分、数独完整解和真实投篮；这些本地自动检查不替代浏览器视觉或服务器回执验收。

快速验收：四方数独每行答案为 `1 2 3 4 / 3 4 1 2 / 2 1 4 3 / 4 3 2 1`；弧线投篮初始角度与力度即可命中，连续五次点击“投篮”可检查终局。封面为本地矢量绘制后生成的 PNG，已嵌入对应 HTML；运行时无字体、图片、库或其他网络请求。
